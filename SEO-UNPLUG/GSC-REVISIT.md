## Six-week checklist

### 1. Load the new export

Expected folder shape:

```
jaikhyapaparampara.com-Coverage-YYYY-MM-DD/
  Chart.csv
  Critical issues.csv
  Metadata.csv
  Non-critical issues.csv
```

Read all four. Use the last row of `Chart.csv` as the new snapshot.

| Redirect | 4 | | | Flat is fine |

### 3. Measure articles separately (primary metric)

In GSC → Page indexing → filter URL prefix:

- `https://jaikhyapaparampara.com/articles/`
- `https://jaikhyapaparampara.com/tags/`

Record indexed and not-indexed for each. This is the only number that answers “are the articles indexed?”

### 4. Impressions

Recompute 7-, 14-, and 28-day averages from the new `Chart.csv`. Compare with the baseline table above. A slow rise is healthy; a >20% drop needs investigation.

### 5. Verify production sitemap

```bash
curl -s https://jaikhyapaparampara.com/sitemap.xml | grep -A1 'bhabishya-malika-64-yoginis'
```

The `lastmod` should reflect the latest article edits, not the publish date. If it is stale:

```bash
npm run sitemap:dates
git add _data/articleLastmod.json
git commit -m "Refresh article lastmod map"
git push origin main
```

Also confirm the sitemap still has ~3,514 URLs unless the taxonomy was intentionally changed.

### 6. Sample live URLs

Check 5 articles, 5 tag pages, `/articles/`, `/tags/`, and `/sitemap.xml`:

- HTTP 200
- `<meta name="robots" content="index, follow">` on articles and tags
- canonical equals the final URL
- no `X-Robots-Tag: noindex`

### 7. Content progress

```bash
npm run context:status
```

Baseline: 44 done, 918 eligible. Record how many context paragraphs were added.

### 8. Decide the next move

Use these rules:

| Condition | Next move |
|---|---|
| Article indexation ≥ 90% and crawled-not-indexed < 200 | Stop sitemap work. Move to internal linking, authority, and content quality. |
| Article indexation 75–90% and crawled-not-indexed > 300 | Continue reader context on high-value articles; consider consolidating single-use tags. |
| Article indexation < 75%, or indexed total dropped | Inspect noindex/canonical/robots on 10 unindexed articles; check the latest deploy; sample URL Inspection. |
| `noindex` still > 1,000 after 6 weeks | Verify live `robots` meta on 10 random thin tag pages; check Cloudflare deploy; do not add more noindex. |
| Impressions down > 20% | Check for accidental noindex, changed titles, or a broken deploy before changing policy. |
| Sitemap URL count changed unexpectedly | Check `.eleventy.js` tag collections, `sitemap.liquid`, and the build log. |

Do **not**:

- mass-request indexing
- re-add `noindex` to tag pages without checking live search traffic
- delete thousands of tags from one sample
- flip index directives every week

## Red flags

- Live sitemap `lastmod` still shows publish dates → `_data/articleLastmod.json` was not refreshed.
- `noindex` count unchanged after 6 weeks → Google is not recrawling, or noindex came back.
- Indexed count falls sharply → check deploy, robots meta, and Cloudflare status.
- Sitemap count drops below ~3,500 without a taxonomy change → build/template regression.
- `Alternate canonical` or 404 grows → export the URL list and add 301s where appropriate.

## Maintenance rule

After any article content edit, including each Phase 4 batch:

```bash
npm run sitemap:dates
git add _data/articleLastmod.json
```

Commit that file with the articles. Cloudflare’s shallow clone cannot read git history, so the committed map is what production uses.
